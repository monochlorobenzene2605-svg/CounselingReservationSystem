# 面談予約システム 要件定義書

## 1.システム概要
職業訓練の受講者がWeb上から面談予約を行い、相談員が予約状況を管理するシステムを構築する。
現在面談予約は紙ベースで行われているが、これをオンライン上から行えるようにすることで、確認や管理の手間を削減し、予約状況を可視化することを目的とする。

## 2.利用者
### 訓練受講者
* 面談可能日時の確認
* 面談予約
* 予約のキャンセル
* 自分の予約の確認
### 相談員
* 面談予約一覧確認
* 面談不可時間の登録･解除

## 4.機能要件

### ログイン機能
#### 受講者
* 受講者ID
* パスワード  
で認証する。  
IDとパスワードは事前に施設側で準備しているものとする。
#### 相談員
* 職員ID
* パスワード  
で認証する。  
こちらもIDとパスワードは事前に施設側で準備しているものとする。

### 面談予約機能
受講者は
* 相談員選択
* 日付選択
* コマ選択
を行い予約できる。

### 予約状況確認機能
受講者は相談員の予約状況を確認できる。  
日付と相談員を選択するとその日の空きコマの状況が見れる。

### 自分の予約の確認機能
受講者は自分の予約を確認できる。
#### 表示項目
* 日付
* 時間
* 担当相談員

### 予約取り消し機能
受講者は予約を取り消しできる。

### 面談不可設定機能
相談員は特定の日付･コマを面談不可として登録できる

### 予約一覧機能
相談員は自分に紐づく予約の一覧を確認できる。
#### 表示項目
* 受講者名
* 予約日時
* 時間

## 5.データモデル案
<u>**下線付き太字**</u>を主キー、*斜体*を外部キーとする。

### users
* <u>**id**</u>
* user_id
* name
* password
    * bcryptでハッシュ化して保存
* role  
    * 受講者か相談員か
### slot_template
コマの定義
* <u>**id**</u>
* period_no  
    * 何コマ目か
* start_time
* end_time
### reservation
* <u>**id**</u>
* *student_id*
* *counselor_id*
* date
* *slot_template_id*
* summary
* details
##### 制約
* counselor_id
* date
* slot_template_id  
の組み合わせを一意とする

### unavailable_slot
相談員の面談不可コマ
* <u>**id**</u>
* *counselor_id*
* date
* *slot_template_id*
##### 制約
* counselor_id
* date
* slot_template_id  
の組み合わせを一意とする


--- 
##### 備考
当初は、以下のように slot テーブルを設け、あらかじめ相談員ごとの空きコマを生成しておく設計を検討していました。<br><br>
slot
* id
* counselor_id
* date
* slot_template_id
* status 
    * 初期値:available

予約が行われた際に status を reserved に更新することで、予約済み状態を管理する想定でした。

しかし、この方式では相談員ごとに一定期間先までのコマをあらかじめ生成する仕組みが必要となります。また、予約の有無にかかわらず事前に大量の空きコマを保持することになるため、設計および運用が複雑になる懸念がありました。

そのため、現在は空きコマを事前生成せず、予約されたコマは reservation テーブル、相談員都合で利用不可とするコマは unavailable_slot テーブルで管理する設計を採用しています。

一方で、この設計には「同一のコマが reservation と unavailable_slot の両方に登録される可能性がある」という課題があります。この点については、アプリ側で登録時に整合性チェックを行い、同一コマが両テーブルに重複して登録されないよう制御する方針としています。


## 6.空きコマ判定仕様
対象日について、  
予約済みコマ + 面談不可コマ  
を取得する。  
取得したコマ以外を予約可能として表示する。
#### 例
予約済:2限  
面談不可コマ:3限  
  
表示結果  
1限:◯
2限:✗
3限:✗
4限:◯
5限:◯
…
